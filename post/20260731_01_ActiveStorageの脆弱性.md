# 投稿文
Rails の Active Storage に Critical の脆弱性。CVSS 9.5。

7.0 以降はデフォルトのまま対象になるので、画像を受け付けてるアプリは先にバージョンを見た方がいいです。

GMO Flatt Securityの解説を軸にまとめます
https://t.co/EeOaukkBPI

===

まず前提。

Rails 7.0 の load_defaults から、Active Storage の画像処理は variant_processor = :vips がデフォルトになってる。

自分で設定した覚えがなくても :vips で動いてる。むしろ何も書いてないアプリほど当てはまる。

===

核心はここ。

Debian や Ubuntu 系の libvips は、ImageMagick に処理を丸ごと投げる magick loader を有効にしてビルドされてる。

設定は :vips なのに ImageMagick は消えてなくて、裏に残ってた。

===

しかも、どのローダーを使うかは拡張子じゃなくファイルの中身で決まる。

libvips は検証が済んでない処理に unfuzzed を付けてるんだけど、Active Storage 側でそれを無効化してなかった。

拡張子チェックも Content-Type 検証もすり抜ける。

===

やること。

・activestorage を 7.2.3.2 / 8.0.5.1 / 8.1.3.1 へ
・libvips を 8.13 以上へ
・secret_key_base とアプリから読める認証情報を交換

上げただけだと、すでに抜かれたシークレットは無効化されない。ここは別作業。

===

上げる前に知っておきたい副作用もある。

修正は危険な処理そのものを止める方式なので、BMP / ICO / PSD の variant が作れなくなる。

保存は成功するのに一覧のサムネイルだけ落ちる、という壊れ方をする。画像を扱うサービスは先に確認した方がいい。

===

攻撃の詳細は 8/28 まで非公開。パッチを当てる時間を作るための判断だと書いてある。

デフォルトが変わったときに、消えたと思っていた依存が裏に残る。
