# 投稿文

Rails の Active Storage に Critical の脆弱性が出てる。CVSS 9.5。

7.0 以降はデフォルト設定のまま対象になるので、画像アップロードを受け付けてるアプリは先にバージョンだけ見た方がいいです。

調べたことをまとめます👇

===

何が起きたか。

Rails 7.0 で画像処理のデフォルトが ImageMagick から libvips に変わった。

けど Debian や Ubuntu 系の libvips は中で ImageMagick に処理を投げるビルドになっていて、消えたと思っていたものが裏に残っていた。

===

厄介なのは、どのローダーを使うかを拡張子ではなくファイルの中身で決めるところ。

.jpg で受け取ったつもりでも別形式の処理が動く。判定してるのは自分のコードじゃなく libvips なので、拡張子チェックも Content-Type 検証も効かない。

===

「サムネイル出してないから大丈夫」にはならないらしい。

添付した時点で解析ジョブが走って libvips がファイルを開く。アドバイザリにも「variant の生成は別途の要件ではない」と書いてあった。ここは勘違いしてた。

===

やること。

・activestorage を 7.2.3.2 / 8.0.5.1 / 8.1.3.1 へ
・libvips を 8.13 以上へ
・secret_key_base とアプリから読める認証情報を交換

上げただけだと、すでに抜かれたシークレットは無効化されない。ここは別作業。

===

上げる前に知っておきたい副作用もある。

修正は危険な処理そのものを止める方式なので、BMP / ICO / PSD の variant が作れなくなる。

保存は成功するのに一覧のサムネイルだけ落ちる、という壊れ方をする。画像を扱うサービスは先に確認した方がいい。

===

攻撃の詳細は 8/28 まで非公開。パッチを当てる時間を作るための判断だと書いてある。

デフォルトが変わったときに、消えたと思っていた依存が裏に残る。他でもありそうだなと思った。

公式のアドバイザリはこちらです。
